- **`QA-TO-PLAN-*` prefix 신설 가치**: `QA-FIX/`는 코드 결함, `reports/QA-TO-PLAN-*`은 인프라/구조 변경 제안. 명확한 분리로 다음 세션이 의도를 한눈에 파악 가능
- **사전 코드 점검의 위력**: cloudflare 전환 전에 4개 지점(allowedHosts / proxy / host-relative WS / CORS) 사전 확인 → "코드 변경 거의 0건" 판정이 기획 결정·개발 부담 가늠에 결정적. 인프라 변경 시 항상 사전 호환성 스캔 권장
- **A 보조 변경 같은 개발 중 결정 갱신은 검수 평가 대상**: 본체 명세를 벗어난 추가 변경도 보안·운영 측면 평가 후 승인 명시. "본체와 다름"만으로 거부하지 말 것
- **자동 검증 + 코드 정합성 일치 = 통과 확정 가능**: 검수가 동일 자동 검증을 재실행할 필요 없음. 개발 세션의 검증 결과 + 명세 라인 단위 일치만 확인하면 충분 (단 의심 사례는 재실행)
