### 04-27: 30분+ 녹음 치명적 오류 — 분석 완료, 1차 수정 반영

**사용자 보고 증상:**
- POST 500 에러 발생 → 블록 편집/분할/병합 불가
- 전사 띄어쓰기 깨짐 + 정확도 저하
- 다음 단계 전환 시 전사 내용 + 작업 내용 전부 유실

**근본 원인 (백엔드 + 프론트엔드 복합):**

| 영역 | 원인 | 영향 |
|------|------|------|
| 백엔드 I/O | 매 audio chunk(5초)마다 session.json 전체 직렬화 (300+ 블록 = 150KB+) | 500 에러 |
| 백엔드 메모리 | `_session_locks` dict 무한 성장, 클린업 없음 | 메모리 누수 |
| 프론트 Web Speech | `event.results` 배열 전체 매번 순회 (30분 = 150+ 항목) | CPU 부하 → 전사 품질 저하 |
| 프론트 에러 무시 | `catch(() => {})` 4곳 → 500 에러 시 사용자 미인지 | 편집 유실 |
| 프론트 단계 전환 | 서버 블록 수 검증 없이 navigate → 미저장 블록 유실 | 데이터 유실 |

**1차 수정 (저위험 방어 코드, 반영 완료):**

| # | 항목 | 효과 |
|---|------|------|
| A | `catch(() => {})` → 토스트 표시 | 에러 발생 시 사용자 인지 |
| B | 단계 전환 전 블록 수 검증 + PUT /blocks API | 데이터 유실 방지 |
| C | Web Speech 루프 `event.resultIndex`부터 순회 | CPU 부하 감소 |
| D | chunk 저장 시 session.json 쓰기 제거 + lock 클린업 | I/O 부하 절반 감소 |

**2차 수정 (구조 변경, 미착수):**
- E: session.json 블록 분리 저장
- F: 블록 렌더링 가상화 (react-window)
- G: WebSocket heartbeat + 자동 재연결
→ 1차 적용 후 실제 30분 녹음 재테스트 결과에 따라 필요성 판단
