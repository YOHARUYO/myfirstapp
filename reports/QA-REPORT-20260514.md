### 3-4. 🔴 1차 fix 적용 후 silent partial 재발 — 근본 원인 재확정

**사용자 재보고:** "녹음 본 저장 안 되는 오류까지 너의 지시를 받아서 개발이 반영해두었는데 이후 서버 재시작한 다음 새로 작성한 회의록에서 녹음한 파일을 다운받으려 하니 POST 404 not found 오류가 떠"

**디스크 신규 의심 사례:** `session_20260507_6e5990a1`이 05-14 17:47에 수정됨. **merged_audio.webm = 41,818 bytes**(정상 28MB도 아니고, 손상 80KB 패턴도 아닌 어중간한 값).

**ffmpeg 수동 재현 (검수가 백엔드와 동일 방식으로 직접 실행):**

```python
subprocess.run([
    "ffmpeg", "-y", "-f", "concat", "-safe", "0", "-i", list_file,
    "-c:a", "libopus", "-b:a", "96k", output_path
], check=True, capture_output=True, timeout=180)
```

→ **ffmpeg exit code 0 (성공 반환) + 41,818 bytes partial 출력** (silent failure). stderr에 명시적 에러 없음.

**두 번째 청크 단독 디코딩:**
```
ffmpeg -i chunk_001.webm
[in#0] Format matroska,webm detected only with low score of 1!
[in#0] EBML header parsing failed
Error opening input file ...chunk_001.webm
```

→ **chunk_001.webm은 그 자체로 ffmpeg가 열 수 없음**.

### 진짜 근본 원인 (재확정)

`MediaRecorder.start(timeslice)`로 슬라이스해도 출력은 **연속된 단일 WebM 스트림**의 단편:
- **첫 청크**: EBML 헤더 + Segment 시작 + Cluster들
- **후속 청크**: 헤더 없는 Cluster bytes만

즉 개별 `chunk_*.webm`은 **독립적인 WebM 파일이 아님**. ffmpeg concat demuxer는 각 입력을 독립 컨테이너로 가정하므로 후속 청크의 EBML 부재 → parse 실패. **재인코딩 여부와 무관하게 발생**.

| 검수가 직접 시도한 ffmpeg 변형 | 결과 |
|------------------------------|------|
| `-c copy` (1차 fix 이전) | 5초만 재생 |
| `-c:a libopus` (1차 fix) | silent 41 KB partial |
| `-fflags +genpts` 추가 | 40.8 KB partial (동일) |
| 개별 청크 → wav 디코딩 후 concat | `EBML header parsing failed`로 시작도 못 함 |

### Raw binary concat 검증 (정답 확정)

```python
with open(output_path, "wb") as out:
    for chunk in sorted_chunks:
        out.write(chunk.read_bytes())
```

**결과 (`session_20260507_6e5990a1` 28.2 MB 입력):**
- 출력 **28.2 MB (100% 보존)**, 처리 시간 **0.33초**
- ffprobe: `codec_name=opus, sample_rate=48000, channels=2` — 유효한 audio stream
- mp3 변환: 40.2 MB / **duration 1756.32 sec ≈ 29분 16초** ← 실제 회의 시간 복구

→ **MediaRecorder가 슬라이스 전에 만들던 원본 단일 stream을 raw bytes로 재조립**하는 것이 정답. ffmpeg를 거치지 않음.

## 8. 검수 교훈 (다음 검수 세션 참고용)

- **silent failure는 exit code만 보면 안 잡힘** — 출력 크기·내용 자체로 검증 필요. 이번 ffmpeg 41 KB partial은 exit 0이라 except에 안 잡혔음
- **MediaRecorder + ffmpeg concat 조합은 부적합** — streamable WebM의 첫 청크 외에는 EBML 헤더가 없음. raw bytes 조립이 표준 패턴
- **입력·출력 데이터 크기 비교를 1차 척도로** — PowerShell로 6개 세션 chunks 합 vs merged 크기 한 번에 비교한 것이 결함 발견의 결정타
- **검수가 ffmpeg subprocess 직접 재현 가능한 환경**의 가치 — 가설을 사실로 전환. 추측 진단 회피
- **검수가 1차 fix 자체 검증을 안 거치고 명세만 작성한 한계** — 1차 fix는 코드 변경 사이즈가 작아 자체 검증 생략했으나, 실제로는 다른 silent failure가 발견됨. 다음 검수부터 명세 작성 전 작은 단위라도 ffmpeg subprocess 재현으로 가설 확정 권장
