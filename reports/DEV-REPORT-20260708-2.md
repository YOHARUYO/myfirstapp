## 3. 주요 기술 결정

### 3-1. `topic` 신규 필드 대신 기존 `source_topic` 사용 (명세 §3.2 노트)

핸드오프 §1은 "추출 단계에서 주제 정보 유실"을 원인으로 지목했으나, 실제 `extract_action_items`는 `###` 주제 헤딩을 추적해 `source_topic`으로 이미 보존하고 있음 (backend `ActionItem.source_topic` + frontend 타입 동일). 유실 지점은 **메시지 빌더가 이 필드를 무시**한 것. 따라서 신규 `topic` 필드를 중복 추가하지 않고 `source_topic` 기준으로 그룹핑 구현 — 기존 데이터 호환(None → 평탄 fallback)도 명세와 동일하게 동작. 6단계 액션 아이템 CRUD UI는 무변경(명세대로 보존만).

### 3-2. topics 스키마 — pydantic Union으로 신구 양형 수용

`SlackMessages.topics: Union[List[SlackTopicMessage], SlackTopicMessage, None]`. 신규 전송은 항상 배열, Phase 1B 저장본(단일 dict)은 읽기에서 그대로 수용 — 마이그레이션 0. `sessions.py complete_session`의 `SlackSentInfo` 검증 경로도 round-trip 테스트로 확인 (§4 #12).

### 3-3. 수정 모달 message_key 규칙

v2 배열 저장본은 `topic_{i}`(인덱스), legacy 단일 dict는 기존 `topics` 키 유지. 방어: v2 배열 저장본에 `topics` 키가 오면 무시(배열 파손 방지, §4 #15). frontend `normalizeTopics`가 저장본 형태를 보고 key를 결정하므로 실제로는 조합 오류가 발생하지 않음.

### 3-4. mrkdwn 변환은 표현 계층에서만

`_md_to_mrkdwn`은 전송 직전 회신 body와 핵심 요약 bullet(방어적)에만 적용. `slack_sent.messages[*].text`에는 **변환된(=슬랙에 실제 게시된) 텍스트**를 저장 — 수정 모달 prefill이 슬랙 실물과 일치해야 하므로. `EXPORT_DIR` .md와 `summary_markdown`은 원본 유지 (§4 #22 검증).

### 3-5. 비정형 요약 안전망

`## 주요 논의` 섹션에 `###` 헤딩이 없는 legacy/비정형 요약은 통짜 1건("주요 논의")으로 폴백해 내용 유실 방지 (§4 #10).
