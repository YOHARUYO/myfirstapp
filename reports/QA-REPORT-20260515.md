### 3-2. 신규 세션 raw concat 산출물 무결성 — 완벽 동작 ✅

| 검증 항목 | 결과 | 판정 |

| chunks 총합 vs merged_audio.webm | 6,643,109 = 6,643,109 bytes | ✅ 1:1 정확 매칭 |

### 3-3. 사용자 보고 "길이 정상·소리 미재생" — 입력 무음으로 확정

| 측정 대상 | mean_volume | max_volume | 의미 |
|---|---|---|---|
| `merged_audio.webm` 전체 | **-50.5 dB** | -1.1 dB | 평균 사실상 무음, 단발 peak만 존재 |
| `chunk_000.webm` (첫 5초, EBML 헤더 보유 정상 단일 청크) | **-59.5 dB** | -27.1 dB | 완전 무음 |
| silencedetect(-50dB) | 6분 52초 중 약 405초(84%)가 무음 | | |

**결정적 근거:** `chunk_000.webm`은 raw concat을 거치지 않은, 그 자체로 독립 디코딩 가능한 첫 5초다. 이것조차 -59.5 dB 무음 → **결함은 raw concat 이전, MediaRecorder가 받은 마이크 입력 자체**. 원인은 마이크 미지원 데스크탑에서 영상 재생으로 우회 검증한 임시 환경(스피커→공기→내장 마이크 경로 + Chrome 기본 noiseSuppression이 먼 소리 제거).

### 3-4. Web Speech vs MediaRecorder 입력 경로 차이

PM 질문("전사는 영상 소리를 잡는데 녹음은 왜 마이크가 필요한가") 분석:

- `useWebSpeech.ts:71` `new SpeechRecognition()` — MediaStream 명시 안 함. 브라우저가 OS 기본 마이크 신호를 Google ASR로 전송. 강한 음성 모델이 -50 dB 약신호도 텍스트화 → "영상 소리가 전사된다"는 체감
- `useAudioStream.ts:45` `getUserMedia({ audio: true })` — 옵션 없는 기본 호출 = Chrome 기본값 `echoCancellation/noiseSuppression/autoGainControl 모두 ON`. raw PCM 그대로 저장. -50 dB는 사람 귀 임계 아래라 "녹음 안 됨"으로 체감
- **양쪽 동일 마이크 사용**. 차이는 후처리(ASR 인식력 vs raw 저장 + noiseSuppression의 먼 소리 제거)
- 차이 좁히기 옵션은 정리하여 PM에 전달(외장 마이크 / getUserMedia 옵션 / OS 부스트 / getDisplayMedia / 스테레오 믹스). 단 `noiseSuppression: false`는 본 운영(대면 회의)에서 환경 소음을 함께 잡아 전사 품질을 떨어뜨릴 위험 → PM 판단 보류

## 8. 검수 교훈 (다음 검수 세션 참고용)

- **"산출물이 비었다"는 보고는 입력부터 의심**: 코드(raw concat)는 1:1로 완벽했고 진짜 원인은 입력 무음. 출력 결함으로 단정하기 전에 입력 데이터 자체를 측정(mean_volume)하는 게 우선
- **독립 디코딩 가능한 단위를 reference로 활용**: chunk_000은 EBML 헤더가 있어 단독 재생 가능 → raw concat 영향 여부를 가르는 결정적 대조군. 결함 위치를 코드 전/후로 빠르게 이분
- **검증 환경과 운영 환경의 괴리 명시**: 마이크 미지원 데스크탑의 영상 우회는 본 시나리오(대면 회의)와 본질적으로 다름. 검수는 환경 차이를 진단에 반드시 포함해야 오진 방지
- **사용자 체감("전사는 되는데 녹음은 안 됨")의 기술적 분해**: 동일 입력·다른 후처리(ASR vs raw)임을 코드로 입증 → 사용자 멘탈 모델 교정
